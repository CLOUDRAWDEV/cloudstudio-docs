## Descripción general del recurso

Azure Cosmos DB Mongo API es un servicio de base de datos NoSQL totalmente administrado que permite almacenar y consultar datos en formato JSON compatible con la API de MongoDB.  
Proporciona escalabilidad y alta disponibilidad mediante distribución global, conmutación por error automática, copias de seguridad y políticas de consistencia.

## Valores de configuración del recurso

#### Configuración básica

-   `capabilities_list` : Lista de API de Cosmos DB que se utilizarán
-   `enable_multiple_write_locations` : Habilitar escritura en múltiples regiones - `true`, `false`
-   `public_network_access_enabled` : Habilitar el acceso público a la cuenta mediante IP pública o endpoint de servicio - `true`, `false`
-   `enable_automatic_failover` : Habilitar la conmutación por error automática - `true`, `false`
-   `virtual_network_filter_enabled` : Habilitar el filtro para permitir acceso solo desde subredes específicas de la red virtual - `true`, `false`
-   `network_acl_bypass_for_azure_services` : Habilitar bypass de ACL para servicios de Azure - `true`, `false`

#### Configuración regional (`geo_location`)

-   `geo_location.failover_priority` : Prioridad de conmutación por error de la región
-   `geo_location.zone_redundant` : Habilitar replicación automática por zonas para tolerancia a fallos - `true`, `false`

#### Política de consistencia (`consistency_policy`)

-   `consistency_policy.consistency_level` : Nivel de consistencia para configurar la disponibilidad y el rendimiento de la base de datos
-   `consistency_policy.max_interval_in_seconds` : Tiempo máximo de staleness permitido (segundos) cuando el nivel de consistencia es Bounded Staleness
-   `consistency_policy.max_staleness_prefix` : Número máximo de solicitudes obsoletas permitidas cuando el nivel de consistencia es Bounded Staleness

#### Configuración de copias de seguridad (`backup`)

-   `backup.type` : Tipo de política de copia de seguridad - `Continuous`, `Periodic`
-   `backup.interval_in_minutes` : Frecuencia de ejecución de la copia de seguridad (minutos) - `60` ~ `1440`
-   `backup.retention_in_hours` : Período de retención de la copia de seguridad (horas) - `8` ~ `720`

#### Configuración de base de datos Mongo (`mongo_database`)

-   `mongo_database.throughput` : Rendimiento de la base de datos Mongo - `400` ~ `1000000`
-   `mongo_database.enable_autoscale` : Habilitar escalado automático del rendimiento - `true`, `false`

#### Configuración de colección Mongo (`mongo_collection`)

-   `mongo_collection.ttl_seconds` : Time To Live predeterminado de la colección MongoDB (segundos)
-   `mongo_collection.shard_key` : Nombre de la clave para el sharding de la colección MongoDB
-   `mongo_collection.throughput` : Rendimiento de la colección MongoDB - `400` ~ `1000000`
-   `mongo_collection.enable_autoscale` : Habilitar escalado automático del rendimiento - `true`, `false`
-   `mongo_collection.included_mongo_database_name` : Nombre de la base de datos Mongo donde se creará la colección

#### Etiquetas

-   `tag` : Etiquetas para clasificar el recurso por categorías - máximo 512 caracteres, `key`:`value`
