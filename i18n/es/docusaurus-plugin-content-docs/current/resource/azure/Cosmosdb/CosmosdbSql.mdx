## Descripción general del recurso

Azure Cosmos DB SQL API es un servicio de base de datos NoSQL totalmente administrado que permite almacenar y consultar datos en formato JSON compatibles con la API SQL.  
Proporciona escalabilidad y alta disponibilidad mediante distribución global, conmutación por error automática, copias de seguridad y políticas de consistencia.

## Valores de configuración del recurso

#### Configuración básica

-   `capabilities_list` : Lista de APIs de Cosmos DB que se utilizarán
-   `enable_multiple_write_locations` : Habilitar escrituras en múltiples regiones – `true`, `false`
-   `public_network_access_enabled` : Habilitar el acceso público a la cuenta mediante IP pública o endpoint de servicio – `true`, `false`
-   `enable_automatic_failover` : Habilitar la conmutación por error automática – `true`, `false`
-   `virtual_network_filter_enabled` : Habilitar el filtro para permitir acceso solo desde subredes específicas de la red virtual – `true`, `false`
-   `network_acl_bypass_for_azure_services` : Habilitar bypass de ACL para servicios de Azure – `true`, `false`

#### Configuración de regiones (`geo_location`)

-   `geo_location.failover_priority` : Prioridad de conmutación por error de la región
-   `geo_location.zone_redundant` : Habilitar replicación automática entre zonas para tolerancia a fallos – `true`, `false`

#### Política de consistencia (`consistency_policy`)

-   `consistency_policy.consistency_level` : Nivel de consistencia para configurar la disponibilidad y el rendimiento de la base de datos
-   `consistency_policy.max_interval_in_seconds` : Tiempo máximo de staleness permitido (segundos) cuando se usa Bounded Staleness
-   `consistency_policy.max_staleness_prefix` : Número máximo de solicitudes stale permitidas cuando se usa Bounded Staleness

#### Configuración de copias de seguridad (`backup`)

-   `backup.type` : Tipo de política de copia de seguridad – `Continuous`, `Periodic`
-   `backup.interval_in_minutes` : Frecuencia de ejecución de la copia de seguridad (minutos) – `60` ~ `1440`
-   `backup.retention_in_hours` : Período de retención de copias de seguridad (horas) – `8` ~ `720`

#### Configuración de base de datos SQL (`sql_database`)

-   `sql_database.throughput` : Rendimiento de la base de datos SQL de Cosmos DB – `400` ~ `1000000`
-   `sql_database.enable_autoscale` : Habilitar escalado automático – `true`, `false`

#### Configuración del contenedor SQL (`sql_container`)

-   `sql_container.partition_key_version` : Versión de la clave de partición – `1`, `2`
-   `sql_container.partition_key_paths` : Lista de rutas de claves de partición utilizadas por el contenedor SQL
-   `sql_container.throughput` : Rendimiento del contenedor SQL – `400` ~ `1000000`
-   `sql_container.indexing_mode` : Modo de indexación – `consistent`, `none`
-   `sql_container.included_path` : Lista de rutas incluidas en la indexación
-   `sql_container.excluded_path` : Lista de rutas excluidas de la indexación
-   `sql_container.unique_key_path` : Lista de rutas de claves únicas para agregar una capa de integridad de datos
-   `sql_container.enable_autoscale` : Habilitar escalado automático – `true`, `false`
-   `sql_container.included_sql_database_name` : Nombre de la base de datos SQL donde se creará el contenedor SQL

#### Etiquetas

-   `tag` : Etiquetas para clasificar el recurso por categorías – máximo 512 caracteres, `key`:`value`
