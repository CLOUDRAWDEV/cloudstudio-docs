## Descripción general del recurso

Azure Cosmos DB Gremlin es un servicio de base de datos NoSQL totalmente administrado que permite almacenar y consultar datos de grafos.  
Proporciona distribución global, escalado automático, copias de seguridad y alta disponibilidad para crear aplicaciones escalables y de alto rendimiento.

## Valores de configuración del recurso

#### Configuración básica

-   `capabilities_list` : Lista de API de Cosmos DB que se utilizarán
-   `enable_multiple_write_locations` : Habilitar escritura en múltiples regiones – `true`, `false`
-   `public_network_access_enabled` : Habilitar el acceso público a la cuenta mediante IP pública o endpoints de servicio – `true`, `false`
-   `enable_automatic_failover` : Habilitar la conmutación por error automática – `true`, `false`
-   `virtual_network_filter_enabled` : Habilitar el filtro para permitir acceso solo desde subredes específicas de una red virtual – `true`, `false`
-   `network_acl_bypass_for_azure_services` : Habilitar bypass de ACL para servicios de Azure – `true`, `false`

#### Configuración regional (`geo_location`)

-   `geo_location.failover_priority` : Prioridad de conmutación por error de la región
-   `geo_location.zone_redundant` : Habilitar la replicación automática entre zonas para tolerancia a fallos – `true`, `false`

#### Política de consistencia (`consistency_policy`)

-   `consistency_policy.consistency_level` : Nivel de consistencia para configurar la disponibilidad y el rendimiento de la base de datos
-   `consistency_policy.max_interval_in_seconds` : Tiempo máximo de staleness permitido (segundos) cuando el nivel de consistencia es Bounded Staleness
-   `consistency_policy.max_staleness_prefix` : Número máximo de solicitudes obsoletas permitidas cuando el nivel de consistencia es Bounded Staleness

#### Configuración de copias de seguridad (`backup`)

-   `backup.type` : Tipo de política de copia de seguridad – `Continuous`, `Periodic`
-   `backup.interval_in_minutes` : Frecuencia de ejecución de copias de seguridad en minutos – `60` ~ `1440`
-   `backup.retention_in_hours` : Período de retención de las copias de seguridad en horas – `8` ~ `720`

#### Configuración de la base de datos Gremlin (`gremlin_database`)

-   `gremlin_database.throughput` : Rendimiento de la base de datos Gremlin – `400` ~ `1000000`
-   `gremlin_database.enable_autoscale` : Habilitar escalado automático – `true`, `false`

#### Configuración del grafo Gremlin (`gremlin_graph`)

-   `gremlin_graph.partition_key_version` : Versión de la clave de partición – `1`, `2`
-   `gremlin_graph.partition_key_path` : Ruta de la clave de partición
-   `gremlin_graph.throughput` : Rendimiento del grafo Gremlin – `400` ~ `1000000`
-   `gremlin_graph.automatic` : Habilitar indexación automática – `true`, `false`
-   `gremlin_graph.indexing_mode` : Modo de indexación – `consistent`, `lazy`, `none`
-   `gremlin_graph.included_paths` : Lista de rutas incluidas en la indexación
-   `gremlin_graph.excluded_paths` : Lista de rutas excluidas de la indexación
-   `gremlin_graph.conflict_resolution_mode` : Modo de resolución de conflictos – `LastWriterWins`, `Custom`
-   `gremlin_graph.unique_key_paths` : Lista de rutas de claves únicas para añadir una capa de integridad de datos
-   `gremlin_graph.enable_autoscale` : Habilitar escalado automático – `true`, `false`
-   `gremlin_graph.included_gremlin_database_name` : Nombre de la base de datos Gremlin donde se creará el grafo

#### Etiquetas

-   `tag` : Etiquetas para clasificar el recurso por categoría – máximo 512 caracteres, `key`:`value`
