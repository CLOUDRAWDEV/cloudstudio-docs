## Panoramica della risorsa

Azure Cosmos DB Gremlin è un servizio di database NoSQL completamente gestito che consente di archiviare ed eseguire query su dati a grafo.  
Fornisce funzionalità di distribuzione globale, scalabilità automatica, backup e alta disponibilità per creare applicazioni ad alte prestazioni e scalabili.

## Valori di configurazione della risorsa

#### Impostazioni di base

-   `capabilities_list` : Elenco delle API di Cosmos DB da utilizzare
-   `enable_multiple_write_locations` : Abilitazione della scrittura multi-area – `true`, `false`
-   `public_network_access_enabled` : Abilitazione dell’accesso pubblico all’account tramite indirizzi IP pubblici o endpoint di servizio – `true`, `false`
-   `enable_automatic_failover` : Abilitazione del failover automatico – `true`, `false`
-   `virtual_network_filter_enabled` : Abilitazione del filtro per consentire l’accesso all’account solo da specifiche subnet della rete virtuale – `true`, `false`
-   `network_acl_bypass_for_azure_services` : Abilitazione del bypass ACL per i servizi Azure – `true`, `false`

#### Impostazioni di area geografica (`geo_location`)

-   `geo_location.failover_priority` : Priorità di failover dell’area geografica
-   `geo_location.zone_redundant` : Abilitazione della replica automatica tra zone per la resilienza agli errori – `true`, `false`

#### Criteri di coerenza (`consistency_policy`)

-   `consistency_policy.consistency_level` : Livello di coerenza per configurare disponibilità e prestazioni del database
-   `consistency_policy.max_interval_in_seconds` : Tempo massimo di staleness consentito (secondi) quando il livello di coerenza è Bounded Staleness
-   `consistency_policy.max_staleness_prefix` : Numero massimo di richieste stale consentite quando il livello di coerenza è Bounded Staleness

#### Impostazioni di backup (`backup`)

-   `backup.type` : Tipo di criterio di backup – `Continuous`, `Periodic`
-   `backup.interval_in_minutes` : Frequenza di esecuzione del backup in minuti – `60` ~ `1440`
-   `backup.retention_in_hours` : Periodo di conservazione dei backup (ore) – `8` ~ `720`

#### Impostazioni del database Gremlin (`gremlin_database`)

-   `gremlin_database.throughput` : Throughput del database Gremlin – `400` ~ `1000000`
-   `gremlin_database.enable_autoscale` : Abilitazione dell’Auto Scaling – `true`, `false`

#### Impostazioni del grafo Gremlin (`gremlin_graph`)

-   `gremlin_graph.partition_key_version` : Versione della chiave di partizione – `1`, `2`
-   `gremlin_graph.partition_key_path` : Percorso della chiave di partizione
-   `gremlin_graph.throughput` : Throughput del grafo Gremlin – `400` ~ `1000000`
-   `gremlin_graph.automatic` : Abilitazione dell’indicizzazione automatica – `true`, `false`
-   `gremlin_graph.indexing_mode` : Modalità di indicizzazione – `consistent`, `lazy`, `none`
-   `gremlin_graph.included_paths` : Elenco dei percorsi inclusi nell’indicizzazione
-   `gremlin_graph.excluded_paths` : Elenco dei percorsi esclusi dall’indicizzazione
-   `gremlin_graph.conflict_resolution_mode` : Modalità di risoluzione dei conflitti – `LastWriterWins`, `Custom`
-   `gremlin_graph.unique_key_paths` : Elenco dei percorsi di chiave univoca per aggiungere un livello di integrità dei dati
-   `gremlin_graph.enable_autoscale` : Abilitazione dell’Auto Scaling – `true`, `false`
-   `gremlin_graph.included_gremlin_database_name` : Nome del database Gremlin in cui verrà creato il grafo Gremlin

#### Tag

-   `tag` : Tag per classificare la risorsa per categoria – massimo 512 caratteri, `key`:`value`
