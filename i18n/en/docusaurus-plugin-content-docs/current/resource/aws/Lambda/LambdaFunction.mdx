## Resource Overview

AWS Lambda is a compute service that lets you run code without provisioning or managing servers. Lambda runs code on a highly available compute infrastructure and handles all compute resource management, including server and operating system maintenance, capacity provisioning and automatic scaling, deployment of code and security patches, and logging. With Lambda, you can run code for almost any type of application or backend service by simply providing code in one of the languages that Lambda supports.

## Resource Setting Values

#### Basic Settings

-   `architectures` : Instruction set architecture for the Lambda function - `x86_64`, `arm64`
-   `runtime` : Runtime identifier for the Lambda function
-   `memory_size` : Amount of memory available to the Lambda function at runtime (MB) - `128` ~ `10240`
-   `handler` : Function entry point in the code
-   `s3_bucket_name` : Name of the S3 bucket containing the function deployment package
-   `file_directory` : Path to the function deployment package in S3 (zip file)
-   `role_name` : Name of the IAM Role applied to Lambda
-   `included_subnet_names` : List of Subnet names connected to the Lambda function (minimum 2)
-   `linked_security_group_names` : List of Security Group names connected to the Lambda function
-   `tracing_mode` : AWS X-Ray tracing mode - `PassThrough`, `Active`

#### Environment Variables (`environment_variable`)

-   `environment_variable` : Environment variables available to the function during Lambda execution (`key:value` format)

#### Tags

-   `tag` : Tags used to categorize resources - up to 512 characters, `key`:`value`
