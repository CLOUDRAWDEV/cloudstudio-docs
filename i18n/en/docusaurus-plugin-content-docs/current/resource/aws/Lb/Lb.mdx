## Resource Overview

Elastic Load Balancing automatically distributes incoming application traffic across multiple targets, such as EC2 instances. It also monitors the health of registered targets and routes traffic only to targets that are in good health.
Elastic Load Balancing supports three types of load balancers: Application Load Balancer, Network Load Balancer, and Classic Load Balancer.

## Resource Setting Values

-   `load_balancer_type`: The type of load balancer to create - `application`, `network`, `gateway`
-   `internal`: Set whether to deploy ELB as Internet facing or Internal - `true`, `false`
-   `included_vpc_name`: Name of the VPC in which to create the target group

-   `linked_subnet_names`: A list of subnet names to attach to the LB
-   `security_group_names`: A list of security group names to assign to the LB. Only valid for Load Balancers of type application

-   `drop_invalid_header`: Set whether HTTP headers with header fields that are not valid are removed by the load balancer (true) or routed to targets (false) - `true`, `false`
-   `target_group`: Name of Target Group, A maximum of 32 alphanumeric characters including hyphens(-) are allowed, but the name must not begin or end with a hyphen

    -   `protocol`: Protocol to use for routing traffic to the targets - `HTTP`, `HTTPS`, `TCP`, `TCP_UDP`, `TLS`, `UDP`
    -   `port`: Port on which targets receive traffic
    -   `instance_names`: List of the target Instance names

-   `listener`: Name of ELB Listener
    -   `protocol`: Protocol to use for routing traffic to the targets - `HTTP`, `HTTPS`, `TCP`, `TCP_UDP`, `TLS`, `UDP`
    -   `port`: Port on which targets receive traffic
    -   `default_action_type`: Type of routing action - `forward`, `redirect`, `fixed-response`
    -   `target_group_name`: Name of the Target Group to which to route traffic

## LB Configuration Guide

<br />

<div style={{ textAlign: "center" }}>
    <img width="400px" src={lb01} alt="lb01" />
</div>

<br />

-   Configure the Load Balancer based on a state where Base → Region → VPC → Subnet → EC2 → Network Interface have already been placed.

<br />
<br />

<div style={{ textAlign: "center" }}>
    <img width="400px" src={lb02} alt="lb02" />
</div>

<br />

-   To allow traffic originating from the external internet to reach resources inside the VPC,
    place an **Internet Gateway**, which acts as the internet entry point for the VPC.

<br />
<br />

<div style={{ textAlign: "center" }}>
    <img width="400px" src={lb03} alt="lb03" />
</div>

<br />

-   Place a **Load Balancer** to receive incoming requests from external sources through a single entry point,
    and distribute traffic across multiple EC2 instances.
-   Connect the Load Balancer to each Subnet configured in different Availability Zones.

<br />
<br />

<div style={{ textAlign: "center" }}>
    <img width="400px" src={lb04} alt="lb04" />
</div>

<br />

-   To define the group of target resources that will actually receive traffic from the Load Balancer,
    place a **Load Balancer Target Group** and connect it in the direction of
    **[Load Balancer -> Load Balancer Target Group]**.

-   Connect the Load Balancer Target Group to the EC2 instances located in each Subnet,
    allowing the Load Balancer to distribute requests accordingly.

<br />
<br />

<div style={{ textAlign: "center" }}>
    <img width="400px" src={lb05} alt="lb05" />
</div>

<br />

-   In the **[Listener - Linked Target Group Name]** option of the Load Balancer,
    select the name of the connected **Target Group**.

<br />
<br />

<div style={{ textAlign: "center" }}>
    <img width="400px" src={lb06} alt="lb06" />
</div>

<br />

-   To ensure that only permitted ports and protocols can access the Load Balancer,
    place a Security Group and connect it in the direction of
    **[Security Group -> Load Balancer]**.
