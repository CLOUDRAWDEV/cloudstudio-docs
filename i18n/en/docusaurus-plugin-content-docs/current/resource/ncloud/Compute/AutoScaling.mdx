## Resource Overview

A service that automatically increases or decreases the number of virtual servers based on user-defined schedules or monitoring results, allowing flexible response to changes in demand. By monitoring servers based on predefined thresholds and automatically adjusting the number of servers, services can be operated stably.

## Resource Setting Values

#### Default Settings

-   `linked_acg_names` : List of ACG names to apply to Auto Scaling
-   `included_subnet_name` : Name of the subnet for server creation
-   `launch_configuration_name` : Name of the Launch Configuration to use
-   `health_check_type_code` : Health check type, server or load balancer - `SVR`, `LOADB`
-   `health_check_grace_period` : Grace period for suspending health checks after a server instance is added to the service - `1` ~ `2147486347`
-   `linked_target_group_list` : List of target group names to connect
-   `min_size` : Minimum size of the Auto Scaling group, range 0 ~ 30 - `1` ~ `30`
-   `max_size` : Maximum size of the Auto Scaling group, range 0 ~ 30 - `1` ~ `30`

#### Auto Scaling Policy (`policy`)

-   `policy.adjustment_type_code` : Scaling adjustment type, change amount (CHANG) / percentage change (PRCNT) / exact capacity (EXACT) - `CHANG`, `PRCNT`, `EXACT`
-   `policy.scaling_adjustment` : Scaling adjustment value
-   `policy.cooldown` : Time (seconds) during which additional alarms are ignored - `0` ~ `214748364`
-   `policy.min_adjustment_step` : Minimum adjustment step when changing the number of instances - `0` ~ `214748364`

#### Auto Scaling Schedule (`schedule`)

-   `schedule.min_size` : Minimum size of the Auto Scaling group - `1` ~ `30`
-   `schedule.max_size` : Maximum size of the Auto Scaling group - `1` ~ `30`
-   `schedule.desired_capacity` : Desired capacity of the Auto Scaling group - `1` ~ `30`
-   `schedule.start_time` : Schedule start date and time
-   `schedule.end_time` : Schedule end date and time
