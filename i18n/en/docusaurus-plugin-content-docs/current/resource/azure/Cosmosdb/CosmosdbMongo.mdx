## Resource Overview

Azure Cosmos DB Mongo API is a fully managed NoSQL database service that allows you to store and query JSON-formatted data supported by the Mongo API.  
It provides scalability and high availability through global distribution, automatic failover, backups, and configurable consistency policies.

## Resource Configuration Values

#### Basic Settings

-   `capabilities_list` : List of Cosmos DB APIs to be used
-   `enable_multiple_write_locations` : Whether to enable multi-region writes - `true`, `false`
-   `public_network_access_enabled` : Whether to allow public access to the account via public IP addresses or service endpoints - `true`, `false`
-   `enable_automatic_failover` : Whether to enable automatic failover - `true`, `false`
-   `virtual_network_filter_enabled` : Whether to enable filtering so that only specific virtual network subnets can access the account - `true`, `false`
-   `network_acl_bypass_for_azure_services` : Whether to allow ACL bypass for Azure services - `true`, `false`

#### Region Settings (`geo_location`)

-   `geo_location.failover_priority` : Failover priority of the region
-   `geo_location.zone_redundant` : Whether to enable automatic zone replication for resiliency - `true`, `false`

#### Consistency Policy (`consistency_policy`)

-   `consistency_policy.consistency_level` : Consistency level for configuring database availability and performance
-   `consistency_policy.max_interval_in_seconds` : Maximum allowed staleness time (seconds) when the consistency level is Bounded Staleness
-   `consistency_policy.max_staleness_prefix` : Maximum allowed number of stale requests when the consistency level is Bounded Staleness

#### Backup Settings (`backup`)

-   `backup.type` : Backup policy type - `Continuous`, `Periodic`
-   `backup.interval_in_minutes` : Backup frequency in minutes - `60` ~ `1440`
-   `backup.retention_in_hours` : Backup retention period in hours - `8` ~ `720`

#### Mongo Database Settings (`mongo_database`)

-   `mongo_database.throughput` : Throughput of the Mongo database - `400` ~ `1000000`
-   `mongo_database.enable_autoscale` : Whether to enable autoscale for throughput - `true`, `false`

#### Mongo Collection Settings (`mongo_collection`)

-   `mongo_collection.ttl_seconds` : Default Time To Live (TTL) for the MongoDB collection (seconds)
-   `mongo_collection.shard_key` : Key name used for sharding the MongoDB collection
-   `mongo_collection.throughput` : Throughput of the MongoDB collection - `400` ~ `1000000`
-   `mongo_collection.enable_autoscale` : Whether to enable autoscale for collection throughput - `true`, `false`
-   `mongo_collection.included_mongo_database_name` : Name of the Mongo database in which the collection will be created

#### Tags

-   `tag` : Tags used to categorize the resource - up to 512 characters, `key`:`value`
