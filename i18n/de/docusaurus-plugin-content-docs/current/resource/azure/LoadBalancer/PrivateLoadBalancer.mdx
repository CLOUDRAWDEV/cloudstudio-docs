## Ressourcenübersicht

Ein Load Balancer bedeutet, dass die Last (eingehender Netzwerkverkehr) effizient auf eine Gruppe von Backend-Ressourcen oder Servern verteilt wird.
Der Azure Load Balancer arbeitet auf Schicht 4 des OSI (Open Systems Interconnect) Modells und dient als einzelner Kontaktpunkt für den Client.
Der Load Balancer verteilt den eingehenden Datenverkehr, der am Front-End des Load Balancers ankommt, auf die Backend-Pool-Instanzen.
Dieser Verkehr wird gemäß den konfigurierten Lastverteilungsregeln und Statusprüfungen weitergeleitet.
Die Backend-Pool-Instanzen können Instanzen von Azure Virtual Machines oder Virtual Machine Scale Sets sein.
Ein Private Load Balancer wird verwendet, wenn nur eine private IP am Front-End benötigt wird.
Der Private Load Balancer wird verwendet, um den Traffic innerhalb des virtuellen Netzwerks zu verteilen.
In einem hybriden Szenario kann das On-Premise-Netzwerk auf das Front-End des Load Balancers zugreifen.

## Ressourcen-Einstellwerte

-   `sku` : Preisstufenkategorie für die Auswahl der Skalierung und Funktionen des Azure Load Balancers - `standard`, `Basic`

-   `private_lb_frontend_ip_config`

    -   `subnet_name` : Name des Subnetzes, das mit der IP-Konfiguration verknüpft ist

-   `virtual_network_name` : Name des virtuellen Netzwerks, an das der Load Balancer den Traffic weiterleitet

-   `backend_pool` : Name des Backend-Pools des Load Balancers

    -   `linked_virtual_machine_names` : Name der virtuellen Maschine, an die der Load Balancer den Traffic weiterleitet

-   `health_probe`

    -   `protocol` : Protokolltyp des Backend-Endpunkts, den der Statusprobe verwendet - `Http`, `Https`, `Tcp`
    -   `port` : Port, den der Statusprobe verwendet, um den Backend-Endpunkt zu überprüfen - `0` ~ `65535`
    -   `request_path` : Pfad für die GET-Anforderung, wenn ein HTTP(S)-Probe verwendet wird
    -   `interval_in_seconds` : Intervall (in Sekunden), in dem der Statusprobe die Antwort der Backend-Pool-Instanzen überprüft - `5` ~ `2147483646`

-   `rule`

    -   `protocol` : Übertragungsprotokoll für den externen Endpunkt - `Tcp`, `Udp`, `All`
    -   `frontend_port` : Port des externen Endpunkts im Bereich von 0 bis 65534 - `0` ~ `65534`
    -   `backend_port` : Port für interne Verbindungen im Bereich von 0 bis 65535 - `0` ~ `65535`
    -   `disable_outbound_snat` : Aktivierung von SNAT für die Regel für ausgehende Verbindungen - `true`, `false`
    -   `frontend_ip_configuration_name` : Name der Frontend-IP-Konfiguration, mit der die Regel verbunden wird
    -   `backend_pool_name` : Name des Backend Address Pools, an den der Load Balancer den Verkehr weiterleitet

-   `nat_rule`

    -   `protocol` : Übertragungsprotokoll für den externen Endpunkt - `Tcp`, `Udp`, `All`
    -   `frontend_port` : Port des externen Endpunkts im Bereich von 0 bis 65534 - `0` ~ `65534`
    -   `backend_port` : Port für interne Verbindungen im Bereich von 0 bis 65535 - `0` ~ `65535`
    -   `frontend_ip_configuration_name` : Name der Frontend-IP-Konfiguration, mit der die NAT-Regel verbunden wird

-   `tag` : Tags zur Kategorisierung von Ressourcen - maximal 512 Zeichen, `key`:`value`
