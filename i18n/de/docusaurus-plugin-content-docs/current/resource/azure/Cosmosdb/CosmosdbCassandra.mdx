## Ressourcenübersicht

Azure Cosmos DB for Apache Cassandra kann als Datenspeicher für Anwendungen verwendet werden, die für Apache Cassandra entwickelt wurden.
Diese Kompatibilität bedeutet, dass bestehende Cassandra-Anwendungen mit der Cassandra-API kommunizieren können, indem sie einen bestehenden Apache-Treiber verwenden, der CQLv4 unterstützt.
In den meisten Fällen können Sie einfach die Verbindungszeichenfolge ändern, um von der Nutzung von Apache Cassandra auf die Nutzung der Cassandra-API umzuschalten.
Mit der Cassandra-API können Sie mit den in Azure Cosmos DB gespeicherten Daten interagieren, indem Sie CQL (Cassandra Query Language), Cassandra-basierte Tools (z. B. cqlsh) und bereits vertraute Cassandra-Client-Treiber verwenden.

## Ressourcen-Einstellwerte

-   `capabilities_list` : Liste der verwendbaren Cosmos DB-APIs - `EnableServerless`, `EnableAggregationPipeline`

-   `enable_multiple_write_locations` : Aktivierung der Multi-Region-Schreiboperationen zur Nutzung der bereitgestellten Durchsatzkapazität für Datenbanken und Container weltweit - `true`, `false`

-   `public_network_access_enabled` : Aktivierung der öffentlichen Verbindung zum Konto über eine öffentliche IP-Adresse oder Service-Endpunkt - `true`, `false`

-   `enable_automatic_failover` : Aktivierung der automatischen Fehlertoleranz - `true`, `false`

-   `virtual_network_filter_enabled` : Aktivierung des Filters, der nur den Zugriff auf das Konto von einem bestimmten Subnetz im virtuellen Netzwerk erlaubt - `true`, `false`

-   `network_acl_bypass_for_azure_services` : Aktivierung des ACL-Bypass für Azure-Dienste - `true`, `false`

-   `geo_location`

    -   `failover_priority` : Fehlerbehandlungspriorität in der Region - `0`~ `0`
    -   `zone_redundant` : Automatische Zonenkopie zur Fehlerbehebung aktivieren - `true`~ `false`

-   `consistency_policy`

    -   `consistency_level` : Konsistenzebene der Cassandra DB zur Einstellung der Verfügbarkeit und Leistung der Datenbank - `Eventual`, `Session`, `Strong`, `ConsistentPrefix`, `BoundedStaleness`
    -   `max_interval_in_seconds` : Wenn die Konsistenzebene Bounded Staleness ist, erlaubte Staleness-Zeit (Sekunden) - `5`~ `86400`
    -   `max_staleness_prefix` : Wenn die Konsistenzebene Bounded Staleness ist, erlaubte maximale Anzahl an Stale Requests - `10`~`2147483647`

-   `backup`

    -   `type` : Backup-Policy-Typ - `Continuous`, `Periodic`
    -   `interval_in_minutes` : Häufigkeit des Backups pro Minute im Bereich von 60 bis 1440 - `60`~ `1440`
    -   `retention_in_hours` : Dauer der Speicherung des Backups (Stunden), im Bereich von 8 bis 720 - `8`~`720`

-   `cassandra_keyspace`

    -   `throughput` : Durchsatz des Cassandra-Schlüsselraums - `400`~ `1000000`
    -   `enable_autoscale` : Ob Auto-Skalierung auf den Cassandra-Schlüsselraum angewendet werden soll - `true`, `false`

-   `cassandra_table`

    -   `throughput` : Durchsatz der Cassandra-Tabelle - `400`~ `1000000`
    -   `column` : Liste der Spaltennamen und -typen im Format 'Name:Typ'
    -   `partition_key` : Partition-Schlüsselname
    -   `cluster_key_name` : Name des zu erstellenden Cluster-Schlüssels
    -   `cluster_key_order` : Kriterien für die Auflistung des Cluster-Schlüssels - `Asc` , `Desc`
    -   `enable_autoscale` : Ob Auto-Skalierung auf den Cassandra-Schlüsselraum angewendet werden soll - `true`, `false`
    -   `included_cosmosdb_keyspace_name` : Name des Cassandra-Schlüsselraums, in dem die Tabelle erstellt wird

-   `tag` : Tags zur Kategorisierung von Ressourcen - maximal 512 Zeichen, `key`:`value`
